# VERDANT

Закрытый мобильный веб-сервис для привычек и саморазвития. React + TypeScript + Vite, данные и вход через Supabase, хостинг на Cloudflare Pages. Платных API нет. «Коуч» работает на устройстве: простая статистическая модель и разговорные шаблоны (`src/lib/coach.ts`), токены не тратятся. Мотивация: XP, уровни, монеты, сундук дня, значки, подарки и мягкие штрафы (`src/lib/game.ts`).

## Запуск локально

```bash
npm install
cp .env.example .env     # впиши URL и publishable-ключ проекта Supabase
npm run dev              # разработка
npm run build            # проверка типов + production-сборка в dist/
```

В `.env` только публичные значения (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`). Service-role ключ в клиент не кладётся никогда.

## База данных

Схема лежит в `supabase/schema.sql` (она же резервная копия схемы). Для нового проекта: Supabase → SQL Editor → вставить файл → Run.

- У всех таблиц включён RLS, политики «только свои строки» (`user_id = auth.uid()`).
- `allowed_emails` закрыта для клиента: без политик, права отозваны.
- Закрытый доступ: триггер на `auth.users` отклоняет создание любого пользователя, чьего email нет в `allowed_emails`. Это работает на уровне базы, а не в интерфейсе.
- Удаление аккаунта: функция `delete_my_account()`, данные удаляются каскадом.

## Геймификация и коуч

- **Награды:** XP и монеты за каждое дело (серия даёт бонус), идеальный день, сундук дня, значки, магазин своих подарков.
- **Пропуски без стыда:** раз в неделю ошибка прощается щитом. Дальше режим выбирает пользователь: без штрафов, −5 монет или маленький «долг» (задание). Штрафы начисляются только за дни, когда человек заходил, а отметка задним числом их снимает.
- **Коуч:** модель оценивает шанс выполнить привычку сегодня (день недели + последние 14 дней), находит лучший и сложный день, час отметок и предлагает мини-версии. Чат понимает основные запросы по ключевым словам. Внешний AI не используется; при желании позже можно подключить бесплатный LLM через Supabase Edge Function.
- **Согласия:** при первом входе один раз (обработка данных и политика), даты сохраняются в профиле. Текст политики: `src/lib/policy.ts`.
- Миграция v2: `supabase/migrations/v2_motivation.sql` (она же в конце `schema.sql`).

## Как добавить друга

1. SQL Editor:
   ```sql
   insert into public.allowed_emails (email) values ('friend@example.com');
   ```
   Email пиши в нижнем регистре.
2. Дальше один из двух способов:
   - **Надёжный:** Dashboard → Authentication → Users → *Add user* → *Create new user*, поставь «Auto Confirm User» и задай временный пароль. Друг входит и меняет пароль в «Профиль → Безопасность». Так никто посторонний не успеет занять чужой email.
   - **Самостоятельно:** друг сам регистрируется на вкладке «Регистрация» и подтверждает email. Встроенная почта Supabase имеет жёсткий лимит писем в час, для нескольких человек обычно хватает.
3. Если все аккаунты создаёшь вручную, можно выключить саморегистрацию совсем: Authentication → Sign In / Providers → Email → *Allow new users to sign up* выключить (вкладка «Регистрация» тогда перестанет работать).

**Отозвать доступ:** удалить email из `allowed_emails` и удалить пользователя в Authentication → Users. Его данные удалятся каскадом.

## Деплой на Cloudflare Pages

1. Залей проект в GitHub-репозиторий (`.env` в `.gitignore`).
2. Cloudflare → Workers & Pages → Create → Pages → Connect to Git.
3. Build command: `npm run build`. Output directory: `dist`.
4. Environment variables: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
5. После деплоя в Supabase → Authentication → URL Configuration укажи Site URL (адрес сайта), иначе ссылки в письмах будут вести не туда.

## Напоминания: что реально работает

- **Всегда:** внутри сайта, пока он открыт. На экране «Сегодня» видно, что ждёт и что пропущено, на вкладке «Сегодня» бейдж с числом ждущих дел, а в момент времени напоминания появляется сообщение.
- **По желанию:** системные уведомления браузера. Нужно разрешение (запрашивается только после нажатия кнопки в профиле) и поддержка браузера. На iPhone они работают только у сайта, добавленного на экран «Домой».
- **Чего нет:** уведомлений при полностью закрытом сайте. Для этого нужен Web Push с серверной частью. Мы не обещаем фоновую доставку там, где браузер её не гарантирует. SMS, WhatsApp и Telegram не используются.

## Резервные копии и удаление данных

- **Экспорт для пользователя:** «Профиль → Скачать мои данные (JSON)».
- **Схема:** `supabase/schema.sql` в репозитории. Для восстановления прогнать файл в SQL Editor нового проекта.
- **Данные базы:** на бесплатном тарифе автоматических бэкапов нет. Раз в какое-то время делай дамп через Supabase CLI: `supabase db dump --db-url "<строка подключения>" -f backup.sql` (строка подключения в Project Settings → Database).
- **Удаление:** «Профиль → Удалить все данные» (аккаунт остаётся) или «Удалить аккаунт» (полностью).

## Проверка перед публикацией

- [ ] `npm run build` проходит без ошибок.
- [ ] Вход с двух разных аккаунтов: данные не пересекаются.
- [ ] Незнакомый email не может зарегистрироваться (ошибка «нет в списке приглашённых»).
- [ ] В Supabase → Advisors нет предупреждений безопасности, кроме ожидаемого про `delete_my_account` (она нужна для удаления своего аккаунта).
- [ ] Сайт проверен на телефоне, включая узкий экран (320 px) и медленное соединение.
- [ ] В клиентском коде нет секретных ключей: `grep -r service_role src` ничего не находит.
